## 重要 AI 建议

- 建议采用“业务 Tool 结果记录器 + 内部图表选择 Tool + 后端编译器”：LLM 只选择类型和标题，后端从真实 Tool 结果选择来源、绑定字段、生成转换和最终数据，避免模型编造或修改业务值。
- 建议定义版本化、与 ECharts 解耦的 `ChartSpec`，通过 dataset、dimensions、encoding、options 和 source 表达通用图表数据。
- 建议以 `traceId + entCode + conversationId` 隔离短生命周期结果，限制字节、行数、字段数、集合宽度、嵌套深度和节点数，终止时清理且不持久化原始业务结果。
- 建议内部图表规划 Tool 放在业务 Tool 快照之外，避免污染业务 Tool 次数、流水、动态 Tool 管理和计费解释。
- 建议前后端一体项目直接收敛为类型化 SSE，并以 `delta → 可选 chart → done` 定义成功事件顺序，异常和取消均安全降级。
- 建议图表随助手消息持久化，历史详情和续聊直接回放已保存对象，旧数据和非法图表返回 `chart = null`。
- 建议本地化 ECharts 及官方扩展，通过固定前端适配器生成声明式 option，禁止后端传递函数、HTML、URL、CSS 或自由 ECharts 配置。
- 建议按 `model/capture/compile/protocol/tool` 拆分图表包，并提取 `AssistantClientProvider`、`AssistantLifecycleService` 和 `chat.dto`，同时增加构造器依赖无环测试。
- 连续 review 中建议收紧会话用户所有权、转换和聚合一致性、图表通道和单位、历史协议、SSE 分片、输入资源预算、派生字段碰撞、单来源以及普通日期形类目类型判断。
- 最新 review 建议为自动模式增加英文 ERP 数据问题识别，并将水位图自动上界限定为可信的 0～1 比例或 0～100 百分比范围。
- 本轮 review 建议补齐不含显式查询动词的英文直接请求、由后端自动绑定多系列和甘特进度、改正甘特图横纵轴语义、复用当前 SSE 错误气泡，并同步项目技术栈上下文。
- 后续 review 建议对 `<!--FINAL_ANSWER-->` 的所有合法非空前缀执行跨分片暂存和终止丢弃，避免取消或异常时向用户泄漏协议残片。

## 开发者决策

- 采纳由 LLM 选择图表、后端基于真实 Tool 数据编译的方案，并将支持范围扩展为包含折线图和饼图在内的 23 种类型。
- 采纳每轮最多一个图表的解释，同一 conversation 的不同问答轮次可以各自保存一个图表。
- 采纳通用 `ChartSpec` 和统一 `ChartVO.ChartType` 枚举，保持小写连字符协议值和历史字符串类型兼容。
- 采纳单来源规划：多 Tool 返回时由后端结合 LLM 标题、结构兼容性和调用顺序选择一份，不在缺少可信单位元数据时自动合并。
- 采纳前后端同步升级为单一类型化 SSE，不保留 V1/V2 分支；旧消息和非法历史图表使用可空字段降级。
- 采纳职责拆分和包结构调整，`ErpAssistantService` 仅保留问答编排，客户端构建和生命周期收口交由独立服务。
- 采纳连续 review 的功能和安全修复，包括会话所有权、图表校验、SSE 解析、历史协议、输入预算、前端安全适配和日期形类目修复。
- 采纳所有新增代码使用中文注释、显式访问修饰符、类末尾新增方法和最小差异的代码规范。
- 采纳标题明确时自动绑定 `series` 且按主轴与系列联合聚合；甘特 `progress` 只接受 0～1，不静默换算 0～100 百分比。
- 采纳移除通用 bar-range 浏览器扩展，甘特图由本地固定函数绘制水平任务范围；SSE 错误在当前助手气泡内展示。
- 采纳最终答案标记真前缀暂存方案，正常完成、异常和取消均只输出净化后的业务正文。
- 采纳 `ParsedRows` 单次解析方案，在保持显式空结果和文本降级语义不变的前提下消除重复 JSON 解析。
- 采纳文档导入的字符、分片、真实 WordPiece Token 和批次写入多层预算；同租户同来源使用覆盖语义，写入失败执行清理。
- 采纳 knowledge 专用问答客户端，不受 ERP 业务范围限制，同时继续保留租户隔离和无 Tool 双重隔离。
- 采纳中英文 README 同步更新和截图重排；顶部环形图不在后续画廊重复，甘特截图固定为 `06-gantt.png`。

## 已讨论风险

- 业务真实性风险：LLM 可能编造或修改数据，最终通过受约束规划和后端真实结果编译规避。
- 租户和用户隔离风险：Tool 结果按 trace、租户、会话读取，历史会话增加用户所有权校验。
- 资源消耗风险：业务结果、规划 JSON 和最终 `ChartSpec` 均设置字节、深度、宽度、节点、行数和维度上限。
- 流式状态风险：异常、取消、缺少 `done` 或 CRLF 跨网络分片可能造成重复保存或错误渲染，最终通过统一 frame、原子收口和跨分片解析处理。
- 历史兼容风险：旧消息无图表字段、坏 JSON、错误类型或日期格式必须保持文本可读，最终通过 `ChartSpecCodec` 完整校验和可空降级处理。
- 前端安全风险：服务端数据不得成为可执行配置，最终仅由本地固定适配器生成 ECharts option，并对展示文本做安全处理。
- 依赖结构风险：新增图表组件和服务拆分可能形成 Spring Bean 环，最终通过单向构造器依赖和自动化依赖图测试约束。
- 业务语义风险：普通类目中的日期形文本可能被错误推断为时间，最终仅在甘特图起止通道识别日期字符串。
- 自动绑定风险：业务指标可能误选为横轴或任务类别，最终通过先选择纵轴指标、甘特类别限定文本、系列基数限制和联合分组消除已知歧义。
- 前端状态风险：错误事件可能生成重复助手气泡，最终通过复用当前消息句柄并保留已接收正文解决。
- 流式协议风险：取消或异常可能停在最终答案标记中间，最终通过真前缀暂存、完成识别和终止丢弃避免协议残片泄漏。
- 资源边界风险：接近上限的业务 Tool JSON 重复解析会放大 CPU 和瞬时内存占用，最终合并为空状态与数据行的一次受限解析。
- 文档导入风险：大文件可能通过请求体校验后仍在解析、分片或向量写入阶段耗尽资源，最终通过字符、分片、真实 Token、批次和失败清理多层边界控制。
- 知识问答风险：ERP 角色提示词可能让模型拒绝已召回的非 ERP 技术文档，最终由 knowledge 专用提示词和客户端隔离解决。
